1
Third Normal Form (3NF) Relational Model

The database is normalized to 3NF to avoid update, insertion, and deletion anomalies. All non-key attributes are fully functionally dependent on the primary key, with no transitive dependencies:

  • Users(user_id, name, email, password_hash, created_at)
  • Accounts(account_id, user_id FK, account_type, balance, opened_at)
  • Categories(category_id, category_name, type)
  • Transactions(transaction_id, account_id FK, category_id FK, amount, txn_type, txn_date, description)
  • Budgets(budget_id, user_id FK, category_id FK, month, limit_amount)
  • RecurringPayments(recurring_id, account_id FK, category_id FK, amount, frequency, next_due_date)
  • Predictions(prediction_id, user_id FK, category_id FK, month, predicted_amount, method)
Integrity Constraints:
  • CHECK (amount > 0), CHECK (txn_type IN ('Credit','Debit'))
  • UNIQUE(user_id, category_id, month) on Budgets and Predictions
  • ON DELETE CASCADE preserving referential integrity.
2
ACID Stored Procedure: transfer_funds

Inter-account transfers are implemented as a single atomic PL/SQL transaction rather than two independent application queries:

-- Row-level locking ensures strict Isolation SELECT balance INTO v_from_balance FROM Accounts WHERE account_id = p_from_account FOR UPDATE; IF v_from_balance < p_amount THEN RAISE_APPLICATION_ERROR(-20005, 'Insufficient balance'); END IF; -- Debit source & Credit destination INSERT INTO Transactions (account_id, ..., amount, 'Debit') ... INSERT INTO Transactions (account_id, ..., amount, 'Credit') ... COMMIT; -- Durable & Atomic EXCEPTION WHEN OTHERS THEN ROLLBACK; -- Preserves consistency
Prevents lost updates, dirty reads, and overdrafts at the database engine level.
3
Automated Triggers

Two triggers maintain business integrity automatically without relying on frontend logic:

1. trg_update_account_balance (Row Trigger):
Fires AFTER INSERT OR DELETE ON Transactions. Automatically updates Accounts.balance (incrementing for credits, decrementing for debits).
2. trg_check_budget_overrun (Compound Trigger):
Fires FOR INSERT ON Transactions COMPOUND TRIGGER. Solves Oracle mutating table restrictions, aggregates monthly category spend, and inserts warning notifications into Alerts table when limits are breached.
4
Cursors, Views & Window Functions
1. Explicit Cursors (generate_recurring_transactions):
Declares a cursor for scheduled payments where next_due_date <= SYSDATE, iterates row-by-row, posts transactions, and computes new schedules with ADD_MONTHS.
2. Database Views (v_budget_vs_actual):
Pre-joins budgets and real-time actual debits, calculating remaining amount, status (ON_TRACK / WARNING / EXCEEDED), and percentage used.
3. Window Functions (AVG() OVER (...)):
Calculates moving averages partitioned by category and ordered by time without collapsing individual rows, feeding the Predictions forecasting table.
